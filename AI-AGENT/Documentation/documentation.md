# Documentation — Build Prompt

Goal: clear, accurate documentation — READMEs, API docs, guides, changelog. Safe.

## 0 · INTAKE — ask before you build
**Batch A — doc (required)**
1. What is being documented (project, API, library, process)?
2. Audience (users vs contributors)
3. Format/location (README, docs/ folder, wiki)
**Batch B — content**
4. Which sections to prioritize (quickstart, install, reference, examples, troubleshooting)
5. Any existing code/docs/comments to draw from (paths)
**Batch C — style**
6. Writing style (formal, friendly, technical)
7. Length/level of detail
8. Examples language (code samples requested?)
## Deliver
- Write real, accurate, runnable instructions; no invented endpoints.
